# 更新记录

## 0.5.0 - 2026-11-26

- 新增 `references/flows.md`：在设计任何界面之前建立的模型（每个对象只有一个归属位置和一个名称、每种来意的最短路径、每个状态都有看得见的下一步操作的状态表、导航模型），附一个完整的诊所预约示例；还有带检查项的规则，涵盖校验、破坏性操作、选择控件、浮层、反馈渠道、时机、加载和乐观更新、键盘和手势、重复输入。
- 新增 `references/motion.md`：什么时候用动效、按角色选缓动、按尺寸定时长、编排、可打断、属性、减弱动态效果、检查和动效毛病。`tokens.css` 新增按角色的缓动（`--ease-out`、`--ease-in`、`--ease-in-out`、`--ease-spring-small`）和 `--dur-4`；`--ease` 和 `--dur-sheet` 仍然可用。
- `scripts/shot.mjs --steps`：通过 DevTools 协议执行点击、悬停、输入、按键、等待、滚动、截图和连拍步骤，用于渲染浮层、状态和过渡帧；新增 `--emulate-reduced-motion`。
- 新建流程增加「为系统建模」；结构这一步要为状态表里的每个状态做设计；实现只用动效令牌。T1 和 T2 用 `--steps` 渲染每个浮层和状态，没有渲染的状态报告为未验证；新增第九个关卡问题，检查状态是否都已渲染、反馈是否在约 100ms 内出现。
- 冷读会收到按任务顺序排列的状态渲染图，并新增第九个问题：任务在哪一步变得不清楚；读者指出的那一步必须修改。
- `principles.md` 开头新增症状对照表（「所有者说 → 先看哪里」）；原则 2 指向状态表；`craft.md` 的动效部分缩减为三条底线和一个指引。

## 0.4.0 - 2026-11-26

- 「先定锚点」成为新建和改进中的必需步骤：优先用项目的设计系统或品牌手册，其次是所有者指定的公开设计系统，最后是 `assets/tokens.css`；数值和禁用清单写进 `DESIGN-NOTES.md`，实现中不用清单以外的值。新建还要求提供真实素材，没有素材时只用字体排印、留白和细线，不用凑数的插图。
- 新增 `assets/tokens.css` 和 `references/tokens.md`：中性的默认令牌（按角色命名的灰色、一个强调色、状态用文字表示、封闭的字号尺度、4px 间距、圆角 6/8、一种浮层阴影、控件高度、时长、焦点环、浅色和深色）。
- 新增 `references/ai-tells.md`：默认套件（米色背景、左侧色条提示框、眉标、状态胶囊、每组都套卡片、虚线表示待定、环形图、KPI 卡片排、渐变、图标底圆等），每项都写了改用什么、怎么检查；除非锚点要求，否则都算发现。
- 新增 `references/craft.md`：编号、可检查的工艺底线；工艺默认值从 platforms.md 移到这里。
- 新增 `references/graphic.md`：文档型页面和吸引型页面，取代 platforms.md 的印刷部分。全文修正了吸引型的表述：强度来自一个元素的尺度和对比以及留白，只用一种品牌色；只有真实素材才用作焦点图。
- 新增 `scripts/lint-design.mjs`：标出尺度外的字号、颜色字面量、阴影、渐变、虚线边框、色条提示框、眉标、胶囊、米色背景、`transition: all`、缺少等宽数字和缺少减弱动态效果的设置。
- 评审关卡：新增第八个问题，检查是否符合规格和 AI 味特征；T1 加上 lint-design 和工艺底线；T2 先运行 lint，并增加由强模型对照锚点渲染图做的品味审查。
- `DESIGN-NOTES.md` 模板新增 Anchor、Tokens、Never 和 Assets。原则 3 改为指向锚点和 ai-tells，不再写固定的样式规定；原则 11 要求只用真实素材。
- 视觉方向来自锚点和内容；取消单独的风格处理环节。

## 0.3.0 - 2026-11-26

- 原则 5 补上正面的一半：写出读者原本要自己算出的结论；必须处理的事项写清是什么、截止时间、后果和哪些不受影响，只用已知事实，推算值写出算式。改前改后的对照例子放在 copy.md。
- 原则 2：每种来意在首屏都有看得见的回答，不紧急的用第二档强调；历史和参考表格放在靠下或较窄的位置。
- 原则 3 和评审问题 3：操作分三级（一个实心的主要操作、少量次要操作、安静的行内操作）；一列完全相同的控件，以及每个工具型视口里超过约 5 个带边框或实心的控件，都算发现。
- platforms.md 印刷部分：列表竖排，不用分隔符连成一串；插图要么大而一看就懂，要么不放；次要信息不大于决定性事实的细节。
- cold-read.md：读者需要自己推算的内容都必须修改，改法是写出结论。

## 0.2.0 - 2026-11-26

- 原则 3 现在兼顾两个方向：只有一个最高强调的元素，并且最先被看到；没有主角算失败；每个视图一个实心的主要按钮；加粗和颜色只用在读者优先关心的地方。
- 原则 2 改为「先来意，再频率」：任务句列出读者的来意，每种来意都能在首屏得到回答；必须处理的事项放在最上面并带操作，这是必需的。
- 原则 4：必须处理的事项在下方那一处只写事实本身，不再加警告或按钮。
- 新增注意力预算的校准（工具型或吸引型），写在 SKILL.md 和 platforms.md；印刷指南要求决定性事实在观看距离下可读、每个角色一种颜色，以及安全边距。
- 新建流程的结构步骤要求明确的视觉方向（颜色角色、字体性格、一个标志性元素）。
- 评审关卡：七个问题，第一步是看 25% 缩放的渲染图 3 秒并检查来意；冷读把「最先看到的」与来意不符视为必须修改，结构性修改之后必须做第二轮。
- 修改模式的冲突清单加入克制与突出。

## 0.1.0 - 2026-11-26

- 首次发布：三种模式（新建、改进、修改），12 条带渲染图检查项的原则，文案规则，平台说明，分档评审关卡和冷读，项目笔记和经验条目流程，`shot.mjs` 和 `lint-copy.mjs`。
