# 平台与媒介

目标不是单一手机宽度的网页时读，选择浮层时也读。圆角和其他组件细节见 `craft.md`；动效见 `motion.md`；印刷品和幻灯片见 `graphic.md`。

> **状态。** 原生移动端和桌面应用两部分沿用同样的原则，再加上各平台的通行做法，检验比网页部分少。真实项目证实或推翻其中内容时，按 `evolve.md` 替换相应文字。

原则不随媒介改变。改变的是读者视野的大小、输入方式（触摸、指针、键盘、无输入），以及成品在哪里使用。要在真实媒介里验证：实际的视口尺寸、实际打开导出文件的应用、打印出来的尺寸。

## 注意力预算：工具型还是吸引型

按界面归类，不按产品归类：票务应用的活动页是吸引型，订单历史是工具型。

| | 工具型（Utility） | 吸引型（Attract） |
|---|---|---|
| 读者 | 已经决定使用，经常回来 | 还没决定，只给几秒钟 |
| 例子 | 设置、仪表盘、账单、行程、表单、收件箱 | 海报、封面页、落地页首屏、应用商店页、首次打开时的空状态、新手引导 |
| 强度 | 安静；对比和颜色只留给主角和必须处理的事项 | 高，来自一个元素的尺度和对比以及它周围的留白，只用一种品牌色；焦点图是真实素材时才用，否则用文字 |
| 密度 | 密而有序；长内容分三层 | 字少；只放决定读者是否感兴趣的 3 个事实，没有与之竞争的内容 |
| 克制针对 | 材质、边框、徽标、重复的强调 | 信息条数和颜色角色的数量，不限制强度 |
| 主角 | 来意的回答或必须处理的事项，带按钮 | 唯一的那条信息或优惠，旁边放决定性的事实 |
| 检验 | 25% 缩放渲染图，看 3 秒：最先看到主角 | 缩略图或远距离观看：是什么、何时或价格，以及要做的动作都读得清 |

两者共同的要求：只有一个主角，每个角色一种颜色，每个数值都来自 `DESIGN-NOTES.md` 里的锚点。安静的工具型界面仍要让主角突出，强烈的吸引型界面仍然元素很少。

## 网页：一套自适应的布局

先做手机版，分两步加宽。要调整这些数值，在 `DESIGN-NOTES.md` 里改，不临时改。

| | 手机（< 640px） | 平板（640–1023px） | 桌面（≥ 1024px） |
|---|---|---|---|
| 左右边距 | 20px | 24px | 32px |
| 内容宽度 | 全宽，单栏 | 单栏，最大约 640px | 最大约 1120px，两栏约 7:5 |
| 主导航 | 悬浮底部标签栏，4 项，适配安全区 | 同左 | 移进顶栏，做成分段控件，指示器相同 |
| 顶栏 | 吸顶，约 48px，半透明并有实色后备 | 同左 | 同左，并容纳导航 |
| 细节层 | 底部弹层，全高减约 16px，顶部圆角，带拖动条 | 右侧抽屉，约 440px，全高 | 右侧抽屉 |
| 卡片网格 | 单栏或横向滚动 | 2 栏 | 3 栏 |
| 次要栏 | 在主栏下方 | 在下方 | 在主栏旁边吸附 |

规则：
- 一种细节模式有两种形态。同一个基于 `<dialog>` 的层，在手机上是底部弹层，从 640px 起是侧边抽屉。Esc、系统返回手势和关闭按钮都能关闭它；焦点回到打开它的那一行。
- 固定栏承载导航。返回（「← 来源名称」，回到读者来的地方，没有来处就回首页）、页面标题和上一个/下一个，在任何宽度下都放在吸顶的顶栏里。宽度小于约 340px 时，返回的文字收起，只留箭头。
- 悬停只是增强。悬停效果包在 `@media (hover: hover)` 里；只适合精确指针的控件（地图缩放按钮）放在 `(hover: hover) and (pointer: fine)` 下显示。悬停才出现的内容，也都能通过点按看到。
- 点击区域至少 44px，即使可见控件只有 32px（用伪元素扩展）。
- 在矮的横屏视口上（宽，但高度不到约 560px），底部弹层会盖住内容，改用窄的侧边面板。
- 图片：首屏只有一张高优先级的头图，其余懒加载；固定宽高比，避免布局跳动；宽屏上限制头图高度（约 320–480px），不沿用手机的比例。
- 无障碍媒体查询：在 `prefers-reduced-motion: reduce` 下，保留约 150ms 的透明度和颜色过渡，去掉位移和缩放；在 `prefers-reduced-transparency: reduce` 下，把玻璃换成实色表面；在 `forced-colors: active` 下，给自定义图形加 `CanvasText` 边框。
- 浅色和深色来自同一套角色令牌；深色模式下不要把照片调暗。
- 要检查的渲染宽度：至少 375、768 和 1280；受众用小屏手机时，加上 320。

## 原生移动端（检验较少）

- 遵循平台的导航模型：iOS 导航栏左上角的返回和从边缘右滑返回；Android 的系统返回和预测性返回。系统已经提供返回的地方，不要自己画一个。
- 底部弹层使用平台的停靠高度（中和大）；细节层规则（细节只用一种模式）仍然适用。
- 点击目标：iOS 44pt，Android 48dp。
- 支持动态字体或字体缩放：在最大的辅助功能字号下测试；行可以变高，但不能截断关键事实。
- 每条边都留出安全区，包括主屏幕指示条和摄像头开孔。
- 底部标签栏放 3–5 个主要使用时刻会用到的目的地（原则 2）。

## 桌面应用（检验较少）

- 窗口可以缩放：定一个最小宽度，在这个宽度和一个较大宽度下都检查布局。
- 常见结构：侧边栏放目的地，中间是主内容，右侧可加一个检查器放细节。检查器就是桌面端的细节层；不要用底部弹层。
- 对话框居中，尺寸贴合内容，只用于简短表单和确认（原则 7 的浮层选择）。
- 每个操作都能用键盘完成；常用操作有快捷键，并在菜单和工具提示里显示。
- 可以比移动端更紧凑，但尺度保持固定；紧凑靠更小的间距，不靠增加尺寸种类。
- 例子：设置窗口在侧边栏列出各分区，每个分区是一个分组，用同一种行形式（左边标签，右边控件），改动立即生效，不设「保存」按钮，除非改动不可撤销。
